# Contributing

The [feature specification](FEATURES.md) describes the visible behaviour. The [architecture](ARCHITECTURE.md) records the component boundaries and decisions; the [README](README.md) contains operating configuration and commands.

## Development

Use Rust with Cargo, Node.js with npm, Python with Pillow, Fontconfig, Docker Compose, PlantUML and Graphviz. Install dependencies and browsers before running the complete verification:

```bash
npm install
npm run prepare:rust
npm run setup:browsers
npm run build:app
npm test
```

`frontend` is an npm workspace. Vite compiles React and TypeScript into `frontend/dist`; RustEmbed embeds that directory into the Rust executable. A frontend change therefore requires rebuilding the Rust executable or image. `npm run dev` runs Cargo with configuration supplied by the development environment. The Compose example is the complete local environment with actual authentication.

TypeScript's incremental build records are local cache files, excluded from version control and the Docker build context.

## Data Model

The List view renders nested unordered lists from the existing parent and sibling-order fields. Pointer Events on the left handle support mouse and touch, with pointer capture and vertical auto-scroll. Keyboard moves use a destination containing a parent and an optional following sibling. All input methods submit the same authenticated `POST /api/projects/{project}/tasks/{task}/move` request with `parent_id`, `before_id` and the captured `expected_sequence`. The server validates the complete subtree depth and rejects cycles, archived destinations, foreign siblings, missing access, CSRF violations and stale sequences. It renumbers destination siblings in document order, increments versions only for changed tasks and commits all resulting `task_moved` events with the state in one transaction. Descendants retain their existing parent links and properties. Revert can restore the recorded parent or order through the ordinary history controls.

SeaORM supplies the SQL connections. Statements use question-mark parameters internally; the PostgreSQL adapter numbers them as dollar parameters. MySQL and MariaDB use `LONGTEXT` for document columns. SQL values are bound separately from statements.

| Table | Key | Stored data |
| --- | --- | --- |
| `people` | `id` | Display username and most recently observed application role |
| `sessions` | Hashed opaque identifier | Login state or authenticated identity, CSRF token and expiry |
| `projects` | UUID | Name, serialized current state and monotonically increasing sequence |
| `events` | Random immutable identifier | Project, unique project sequence, task identifier and serialized revision |

A project state contains `tasks`, `members`, `preamble` and `sprints`. Membership values are `member`; effective capability comes from the current authenticated role. Every task has a UUID, optional parent UUID, title, description, details, status, optional priority, complexity, optional due date, owner identifiers, Markdown reference, next-week marker, archive flag, sibling order, version, update timestamp, optional sprint and prerequisite identifiers. The API's generated schemas specify their wire types. New tasks default to Open, Medium priority, complexity one, empty text, no date, owners, sprint or dependencies, no archive/week marker, version zero and a generated stable reference. The selected hierarchy node becomes the initial parent.

The identity identifier is the URL-safe SHA-256 digest of issuer, a NUL separator and immutable subject. Usernames remain display values. Sessions retain the subject and provider groups; each authenticated request resolves the configured role again. Configuration is read at process startup, so changed environment values require restarting the process. Changed provider groups are observed at the next sign-in.

User labels add an ID prefix when another remembered identity has the same username, extending the prefix until it differs. Historical author names use the same rule against current remembered users. Owner validation applies to saves and restoration; selecting historical unknown owners fails before persistence, while restoring other valid fields remains available. Markdown resolves an owner name only when exactly one remembered identity matches it and refuses export of an ambiguous owner name. JSON keeps immutable owner IDs throughout.

## Transactions

Task saves require `expected_version`; project renames, sprint changes, membership changes and committed imports require `expected_sequence`. The service loads the current project, verifies access and validates candidate state. It updates the project name and state with a condition on its previous sequence and inserts the immutable events in the same SQL transaction. No affected project row means HTTP 409; the transaction does not append an event. Successful saves increment the task version and record a full before/after snapshot, including an unchanged save. Reusing a new task's UUID with the same original content is idempotent; different content returns a conflict. Project renames update the first preamble heading or insert one, record complete before/after metadata and reject blank, multiline or oversized names.

Validation rejects invalid UUIDs, unsupported status/priority/complexity, duplicate references, invalid dates, unknown parents, hierarchy cycles, excessive depth, unknown owners, unknown sprints and dependency cycles. The depth limit includes the moved node's descendants. Details reject CommonMark level-one headings outside literal code or HTML blocks. Dependency enforcement applies when entering In Work or Done, while text changes on existing work remain possible after a prerequisite reopens.

Restoration loads a revision belonging to the same project and task, copies explicitly selected mutable fields into the current task, validates the resulting state and appends `task_restored`. Identity, task version and update time are server controlled. Project and sprint events retain complete before/after objects even though the task editor offers restoration only for tasks.

## Interchange

The Markdown parser accepts two-space indentation and the status/priority/complexity/date/title/description/owners/reference/week grammar documented in the README. Escaping preserves literal backslashes, brackets and title separators. Missing references receive a deterministic `task-` UUIDv5 reference from the JSON-encoded tuple of namespace label, parent reference, unescaped title and zero-based occurrence among same-title siblings without explicit references. Existing references recover existing task UUIDs. Explicit references are required to preserve identity through arbitrary external renames or moves. Detail chapters follow the list; pulldown-cmark offsets distinguish real headings from literal fenced code, indented code and HTML. Only surrounding blank lines are removed from details; significant indentation and hard-break spaces remain.

Markdown merge preserves absent tasks and their planning data. Replace archives absent tasks. Owner usernames resolve against known identities; unresolved owners appear in preview and prevent application. Markdown export excludes archived subtrees and reparses its generated output to detect source loss or an unfinished block consuming a later chapter. JSON is the complete alternative for source that cannot round-trip as task Markdown.

An undated title beginning with an eight-digit token receives an extra leading delimiter space during serialization. This uses the existing grammar's title whitespace to prevent its prefix being parsed as the optional date. Round-trip verification compares every represented property, including dates, status, priority, complexity and the week marker.

JSON uses `format: todo-project` and schema version one. It carries the project name, snapshot sequence, state, known users and complete history. Imports validate the candidate graph, sprint constraints, history timestamps and task snapshot identifiers before preview. Target membership is retained. Imported history receives new local IDs/sequences, retains source author/time and records both importing actor and source revision ID. Source IDs deduplicate repeated history imports. Normal imported-task snapshots and a project import event record the operation. Exported history is bounded by the loaded snapshot sequence to keep the document consistent under concurrent writes.

## Browser Behaviour

The shared stylesheet defines palette fallbacks, semantic colour roles and named measurements in its root. Component rules consume those definitions. Body text retains the browser's root font setting; the small and emphasis sizes derive from it. One body line defines the spacing rhythm, including half-line separation and three-line spacing before headings. Breakpoints name the layout transition in comments. Milkdown receives the same semantic roles and typography through its theme properties; its functional component styles remain supplied by the editor package. List indentation follows nested list structure and available container width, without React styling properties.

REST reads and writes use same-origin fetch. Mutation requests include the CSRF token obtained from `/api/me`; the browser supplies the Origin header. The API wrapper bounds requests to 25 seconds and presents server error messages. Editors keep their original task version and draft until save succeeds or the user explicitly reloads/discards. Formatted mode reads Milkdown synchronously at Save, mode changes and close so debounced change listeners cannot omit the final keystrokes. In-flight saves disable input and closing.

WebSockets announce sequence, task ID and action after commit. The client reconnects with its last received sequence and reloads a current project snapshot; a 30ms refresh coalesces event bursts. The browser's offline event closes its active socket and stops retries; its online event opens a new socket. Callbacks from an older socket cannot change the current connection state. The server combines an immediate in-process broadcast with 500ms durable event polling across processes. Access and session validity are checked while connections remain open. Reconnect refreshes recover changes missed while disconnected. Current project snapshots include tasks, sprints and membership at one sequence.

`npm run prepare:renderer` compiles the canonical `renderer/task-tree.py` source into its `task-tree-view` custom element for React. A standalone checkout includes this source and its recorded SHA-256 in `renderer/provenance.json`. An optional `TODO_RENDERER_SOURCE` stages an external canonical source; the renderer test additionally compares its bytes when set. An intentional canonical renderer update also updates the recorded digest after review. The suite verifies complete SVG/HTML parity and the exact shared custom-element module. `renderer/render.py` translates stored tasks to its node format and calls its existing layout, SVG and HTML functions. The same Noto Sans font files and their licence are bundled. `src/renderer.rs` bounds execution time, serializes rendering and caches recent results. Diagram requests verify the authenticated project's scope before invoking the renderer. The standalone HTML and React use that same custom element. Its module receives a script hash in standalone responses; all pages deny framing. A bridge connects its navigation and gestures to the editor. Packing and label plans come from the canonical renderer. Ordinary task saves and restoration supply weekly work titles; imports retain the next-week flag without marking every imported task as worked this week. SVG and standalone HTML exports are the renderer's original outputs. PNG rasterizes that SVG at its original dimensions.

Load captures the known project sequences before invoking the native file chooser. The document title selects an existing project or creates one for an administrator; existing tasks merge by stable identity. File contents determine JSON or Markdown; the server validates the complete candidate before committing it. No preview dialog is involved. Invalid files retain data and history. Markdown preamble changes receive a separate event in the same transaction as all task changes. Clearing the file input after completion permits selecting the same file again.

The document's first level-one preamble heading is the project name. The Markdown parser supplies its text, excluding code examples and formatting markers. Existing project reads resolve that title as well. Creation and heading-free imports add a heading from the project name, or the JSON name when supplied; generated headings escape Markdown punctuation. Rename replaces the parsed heading and preserves the surrounding preamble. Import commits the name, state and full before/after metadata history together. Project selection, navigation, the browser tab and both data exports consume the same value.

At narrow widths the board uses a single grid column and the existing status groups retain their order and controls. A native hierarchy selector exposes every ancestor without extending the header. The task-tree bridge wraps the original legend in a details element and derives the chart's aspect ratio from the original viewBox, leaving packing, labels and colours unchanged. The wrapper and legend state survive live patches. Narrow text, code and table content wrap within their regions. Browser checks sweep phone widths and landscape, quantify horizontal overflow across visible HTML regions in both documents and retain the wide-screen arrangement.

The application uses one viewport grid with a collapsible sidebar and a compact document-title breadcrumb. Task views fill the remaining area; board columns and diagram legend scroll internally. The editor uses aligned properties beside a persistent Milkdown command toolbar and detail area, with Save before Cancel. Narrow screens stack controls and allow editor scrolling.

Remote snapshots update component data without remounting an open editor. Draft baselines, focus, selection and scroll positions remain local until an explicit save, reload or navigation. The diagram element retains its shadow root across view switches; its bridge fetches the original renderer's new node data, patches circles by task UUID, reuses native fill/stroke/label functions and preserves the exact current viewBox. Editable Markdown references are mapped to immutable task UUIDs. A generation counter discards obsolete diagram responses. History retains its loaded pages and selected revision while offering Show new revisions for an explicit refresh.

## Authentication

Use Authorization Code with PKCE S256, random state and nonce, exact redirect URI and signed OIDC ID tokens. Discovery issuer and endpoint origins must match the configured issuer. Allowed token algorithms are RS256, RS384, RS512, ES256 and ES384; validation requires issuer, audience, subject and expiry and checks nonce separately. Back-channel redirects are refused. The internal provider origin is an explicit deployment option and preserves the public issuer and authority.

The browser stores an opaque HttpOnly, SameSite=Lax cookie; production cookies also require Secure. Database session keys store only its digest. Login state is consumed before code exchange. Write requests require exact Origin and the session's CSRF token. WebSocket handshakes require the same authenticated session and exact Origin. Logout deletes the application session. The README documents provider-role caching, request/body/connection limits and the local HTTP exception.

## Verification

`npm run test:styles` checks the owned stylesheet for unnamed component measurements, direct colour definitions, direct palette access, root font overrides and independent spacing values. It runs in the main suite. The viewport editor journey applies browser font preferences and a replacement palette, measures the actual editor text and heading rhythm, and verifies that a wider viewport retains the same type size. Source contracts supplement the rendered review; they do not establish visual acceptance.

`npm test` builds the application and image, validates the generated API, audits dependencies, runs Rust tests and executes real Authentik browser journeys in Chromium and Firefox against PostgreSQL, MySQL and MariaDB. Database/service restarts compare the complete task/sprint snapshot, sequence and every exported history record with the values saved beforehand. `npm run test:proof` additionally alternates unavailable and running application states twice before the matrix. Tests use distinct projects and explicit identities; no authentication, storage or browser API is mocked.

The owner handler tests use real in-memory SQLite persistence and an explicit authenticated test session to measure rejection without a write and lossless JSON identity round trips. Browser cases exercise the full OIDC flow, actual Authentik account rename/name reuse, visible identity selection and selective restoration from imported history against the database matrix.

The shared test environment fixes the initial PostgreSQL URL to the test project's `database` service and fixes published ports to loopback, regardless of inherited deployment overrides. Matrix phases select that same project's MySQL and MariaDB aliases explicitly. A contract passes conflicting external settings to this environment builder and resolves the real Docker Compose configuration, checking the resulting database host and both published interfaces without starting containers or connecting to databases.

`npm run demo` uses the same local environment policy, builds missing images, waits for application and identity-provider readiness and signs in through the actual browser flow. It resolves the source Compose file once, removes build directives from the runtime configuration and gives that configuration a separate Compose project, directory, networks and data volumes. The runtime has no host bind mounts or source-tree dependency. The temporary directory is recorded in ignored artefacts; `npm run demo:stop` uses it and retains data. It imports tasks only into an empty project, detects previously created sample tasks and sprints, and advances the initial text examples only when their expected versions and content remain unchanged. The regular deployment commands retain their existing behaviour. The default published application port is 8326; the binary still listens on container port 8080.

The runner creates one uniquely named Compose project and cleans up only that project. Export files, reports, traces, image archive and scanner output remain under ignored `artifacts` and `test-results`. The design scanner captures Bubbles, Board, editor modes, task revisions, project History, Sprints, Members, import, context menu, hover and API reference states. Explicit readiness selectors establish each captured state; network idleness and preliminary scrolling are disabled for the live connection and transient overlays. The normal viewport, scroll, inner-region and print captures remain enabled. Review the resulting images as well as the automated layout assertions. The [test registry](TESTS.md) maps behaviour to tests. Dependency exceptions and review dates are documented in [Security Workarounds](SECURITY-WORKAROUNDS.md).

`npm run test:renderer` compares complete SVG and HTML byte for byte against the original build entry point. `TODO_IMPORT_FILE` selects a local task file for both renderer parity and browser upload/export acceptance. When that variable is unset, a file at `artifacts/import-TODO.md` is included automatically; otherwise portable fixtures are used. Such operator data remains ignored and is excluded from the image. Browser tests upload the file through the actual chooser and compare all exported task entries after reload.

Before rebuilding a correction, `npm run test:baseline` preserves the current local application image. The proof run then executes import, renderer and offline-recovery regressions against that running baseline and the corrected image twice, followed by the complete regression and database matrix. Every regression case must fail on the baseline and pass on the correction. The baseline tag and file are local test artefacts.

The Docker-family GitHub caller selects services with both a build context and an explicit image name. Only `todo` has both; demonstration Authentik services retain Compose-generated local names. The CI bootstrap runs only when `GITHUB_ACTIONS=true`, installs PlantUML/Graphviz and browser system dependencies on that disposable runner, and then runs the same complete suite. The reusable workflow handles native architectures, source labels and publication after successful tests. Local verification never calls the publishing command.

Project file loading uses the document title as its project key and merges existing tasks. New, Rename and Delete require the global administrator role. The legacy project-specific import endpoints retain their replace and dry-run contracts. Session invalidation clears browser state independently of ordinary project updates; unsaved drafts survive ordinary remote changes and end with their session. Board single-click editing waits for the double-click interval so child navigation opens directly.
